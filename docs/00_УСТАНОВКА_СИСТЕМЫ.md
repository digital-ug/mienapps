# MIENAPPS — Как установить систему разработки (для owner'а, по шагам)

> Тебе не нужно понимать содержимое файлов. Это инструкции для двух «версий меня»: Claude.ai (планировщик,
> этот чат) и Claude Code (пишет код). Твоя задача — разложить файлы по местам и один раз поставить скилы.
> Так устроена дисциплина у Sovyra; здесь то же самое, но под веб-проекты.

---

## Что это за файлы (коротко)

| Файл | Кто читает | Куда положить |
|---|---|---|
| `RULES_FOR_CLAUDE_AI.md` | Claude.ai (этот чат) | Project Knowledge **этого** проекта |
| `PROJECT_CONTEXT.md` | Claude.ai + Claude Code | Project Knowledge + в репо `docs/` |
| `OBSERVABILITY.md` | Claude.ai + Claude Code | Project Knowledge + в репо `docs/` |
| `ACTIVE_WORK.md` | оба (Claude Code пишет сам) | в репо `docs/` + копия в Project Knowledge |
| `TASK_TEMPLATE.md` | Claude.ai (по нему пишет ТЗ) | в репо `docs/` |
| `SKILLS.md` | Claude Code | в репо `docs/` |
| `CLAUDE.md` | Claude Code | в **корень** репо (не в docs/) |

> «Project Knowledge» — это вкладка знаний у проекта в Claude.ai (там, где сейчас лежат документы MienApps).

---

## Шаг 1 — Положить файлы в Project Knowledge (браузер, 2 мин)
1. 🧑 Открой проект MienApps в Claude.ai → раздел знаний проекта.
2. 🧑 Загрузи туда: `RULES_FOR_CLAUDE_AI.md`, `PROJECT_CONTEXT.md`, `OBSERVABILITY.md`, `ACTIVE_WORK.md`.
3. ✅ Теперь в начале любого нового чата я (Claude.ai) читаю их и работаю по дисциплине.

## Шаг 2 — Положить файлы в репозиторий (через Claude Code)
1. 🧑 Открой папку репо `mienapps` в VS Code → запусти Claude Code.
2. 🧑 Скопируй в репо распакованные файлы: `CLAUDE.md` — в корень; остальные `*.md` из этой системы — в папку `docs/`.
   (Если не уверен — вставь Claude Code промпт ниже, он разложит.)

> 📋 Промпт для Claude Code:
> «В корне репо создай папку `docs/`. Положи туда файлы PROJECT_CONTEXT.md, OBSERVABILITY.md, ACTIVE_WORK.md,
> TASK_TEMPLATE.md, SKILLS.md, RULES_FOR_CLAUDE_AI.md (я добавлю их в проект). Файл CLAUDE.md положи в КОРЕНЬ
> репо (замени старый из стартера). Создай пустые папки `tests/unit`, `tests/e2e`, `tests/eval`. Закоммить в ветку dev.»

## Шаг 3 — Поставить скилы Claude Code (один раз)
1. 🧑 Вставь Claude Code промпт установки скилов из `SKILLS.md` §2 (большой промпт про клонирование ECC).
2. 🧑 Claude Code покажет, какие скилы включились. Если что-то заблокировал GateGuard на сетапе — скажи мне,
   дам обходной запуск.

## Шаг 4 — Включить Sentry для веба (через ТЗ)
1. 🧑 Скажи мне в чате: «Готовь TASK для Observability Фаза 1».
2. 🤖 Я напишу ТЗ (по TASK_TEMPLATE) — Claude Code расставит Sentry-теги во всех роутах и на клиенте.
3. 🧑 Заведёшь в Sentry один проект `mienapps-web`, дашь мне доступ через Sentry MCP (как в Sovyra) — и я
   буду видеть все ошибки всех продуктов сам, без твоих скриншотов.

## Как теперь выглядит твой рабочий цикл (запомни эти 4 строки)
```
1. Ты замечаешь баг → пишешь мне (текст/скрин/видео).
2. Я смотрю Sentry → пишу ТЗ-файл → ты вставляешь его в Claude Code.
3. Claude Code чинит, проверяет (тесты+evals), пушит в dev → staging обновляется → ты проверяешь.
4. Работает? Claude Code мёржит dev→main = публикация. Не работает? Шлёшь мне — итерируем (макс 3 раза, потом редизайн).
```

## Что делает систему «защищённой от ошибок» (почему это работает)
- **Sentry FIRST:** я не гадаю — сначала смотрю реальную ошибку по тегам `product/feature/tz`.
- **GateGuard:** Claude Code обязан изучить реальные данные ДО правки (лечит «предположил структуру»).
- **TDD + evals:** код и КАЧЕСТВО ПРОМПТА покрыты тестами; изменил промпт — прогон evals обязателен.
- **verification-before-completion + CI:** «готово» невозможно без зелёных проверок; merge в прод — только через зелёный CI.
- **Sentinel-lite:** после деплоя дневная сводка в Telegram + золотой путь; тишина = всё хорошо, а не «монитор умер».
- **ACTIVE_WORK.md:** Claude Code сам ведёт лог — ты и я всегда знаем, что сделано и что в работе.
