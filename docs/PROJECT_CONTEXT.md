## 1. ЧТО ТАКОЕ MIENAPPS

MienApps — это семейство импульсных AI-микро-продуктов: человек платит ~€5 за готовую сильную эмоцию +
красивый шерабельный артефакт (карта, письмо, вердикт, голосовое), который сам собрать не может и не может
нагуглить как продукт. Разгон — короткими роликами в TikTok/Reels (Бразилия/ЛатАм/Индонезия), монетизация —
на англоязычной странице.

**Продукты (реестр):**
| Slug | Название | Ввод | Артефакт | Статус |
|---|---|---|---|---|
| `inner-world-map` | Карта внутреннего мира | 5 ответов | Фэнтези-карта (Satori) | образец в стартере |
| `inner-child-letter` | Письмо внутреннего ребёнка | детское фото + 1 фраза | Письмо-записка (Satori) | следующий к сборке |

**Юрлицо:** немецкий UG. Платежи через Merchant of Record (Paddle) — он берёт VAT/чеки. Биометрия (фото лиц) —
особая категория GDPR ст.9: явное согласие, удаление загрузок сразу после генерации, не для дообучения.

## 3. АРХИТЕКТУРА — МОНОРЕПО

**Один репозиторий `mienapps`. Продукт = папка. Общий код — один раз.**

```
mienapps/                         ← ОДИН GitHub-репо
├─ src/lib/*                      ← ОБЩИЙ слой (AI-gateway, payments, queue, storage, email,
│                                   ratelimit, artifact-render). Чинишь тут — чинится у ВСЕХ продуктов.
├─ src/products/<slug>/*          ← код конкретного продукта (config, prompt, pipeline, artifact)
├─ src/products/index.ts          ← реестр (PRODUCTS + ACTIVE = NEXT_PUBLIC_PRODUCT)
├─ src/app/*                      ← общий поток (order→checkout→webhook→jobs→status→cleanup)
├─ tests/{unit,e2e,eval}/         ← unit (Vitest) · E2E (Playwright) · evals (prompt-качество)
├─ .claude/                       ← скилы и конфиг Claude Code (см. SKILLS.md)
├─ supabase/migrations/*          ← миграции БД
└─ docs/ (эти файлы)              ← RULES / PROJECT_CONTEXT / OBSERVABILITY / ACTIVE_WORK / TASK_TEMPLATE
```

**Деплой:** на Vercel — **по одному проекту на продукт**, все импортят ТОТ ЖЕ репо, отличаются:
- переменной `NEXT_PUBLIC_PRODUCT=<slug>`,
- доменом (`innerchildletter.app` и т.д.),
- (Paddle) своим price_id.
Production-ветка = `main`, preview = `dev` (staging). Фикс в `lib/` → пуш в `dev` → все staging-деплои
обновляются → проверил → merge `dev→main` = публикация у всех продуктов сразу.

**Почему монорепо, а не репо-на-продукт:** общий `lib/` живёт один раз — нет дрейфа (главная боль polyrepo).
Изоляция продуктов — на уровне папок: задача в `products/A/` не пересекается с `products/B/`.

### Стек
- **Frontend/Backend:** Next.js (App Router, TypeScript) на **Vercel**.
- **БД + файлы:** **Supabase** (Postgres + Storage). RLS для будущего B2B.
- **Платежи:** **Paddle** (Merchant of Record) — overlay-checkout + webhook как источник правды.
- **Очередь:** **Upstash QStash** (тяжёлая генерация вне HTTP-таймаута). Лимиты/кэш: **Upstash Redis**.
- **Email:** **Resend**. **Cron/keep-warm/cleanup:** **cron-job.org**.
- **AI:** Claude (тон/эмпатия) · Gemini 2.5 Pro (Vision/длинный контекст) · Groq (быстрый дешёвый текст,
  транскрибация). Картинки: Flux (Replicate) опц. Артефакты с текстом: **Satori / `next/og`** (детерминированно).
  Голос (future-self): ElevenLabs, ≤60 сек, держать себестоимость.
- **Наблюдаемость:** **Sentry** (Next.js: client + server) + Vercel logs → Sentry + **PostHog** (продуктовые метрики).

### Ключевой поток заказа
`order(draft)` → Paddle overlay → webhook `transaction.completed` (verify подпись = ИСТОЧНИК ПРАВДЫ об оплате)
→ `status=paid` → enqueue(QStash) → `/api/jobs/process` (verify подпись) → `pipeline(product)`: AI-gateway →
строгий JSON → `renderArtifact` (Satori→PNG) → Supabase Storage → `status=done` → Resend. `/result/[id]` поллит
`/api/status/[id]`. Загрузки удаляются после генерации (TTL).
